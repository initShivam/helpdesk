# Twilio WhatsApp Sandbox setup

1. In Twilio Console, activate the WhatsApp Sandbox and follow its displayed join instructions from the personal test WhatsApp account. Use the exact Sandbox sender Twilio displays.
2. Create or select an approved Sandbox-compatible WhatsApp Content Template. Configure template variables `1` (ticket number) and `2` (ticket subject), then copy its Content SID.
3. Set `WHATSAPP_ENABLED=True`, `WHATSAPP_PROVIDER=twilio`, `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_WHATSAPP_FROM` (for example `whatsapp:+...` from the Console), and `WHATSAPP_TEMPLATE_SID` in the backend environment. Keep these values server-side and out of source control.
4. Set `TWILIO_STATUS_CALLBACK_URL` to the HTTPS URL ending in `/api/whatsapp/webhook/`. For local testing, expose the local app using a secure HTTPS tunnel (such as an authenticated, access-controlled tunnel) and restrict it to the callback route where possible. Never expose Django's development server directly to the public internet.
5. Enter a consenting test customer's WhatsApp number with country code on the ticket detail page. Resolution only triggers WhatsApp when the provider is fully configured and both number and consent are present.
6. Resolve an open test ticket. Check the WhatsApp notification panel for the Twilio acceptance status and message SID in server-side tracking, then verify actual receipt in the test WhatsApp account. A `sent` status means Twilio accepted/sent the request; only a signed callback confirms delivery or read.
7. If Twilio rejects a message, the ticket shows its error code and a sanitized provider detail. Correct the indicated template/sender/recipient configuration before retrying. After the automatic attempts are exhausted, **Retry after fixing Twilio** explicitly starts a new manual attempt cycle. Do not use automated tests to send real messages.
8. For Twilio error `572002`, the trial account has not verified the destination number. Verify the recipient in Twilio Console or upgrade the account before retrying. For the WhatsApp Sandbox, the recipient must also have joined the active Sandbox.

Twilio signs callbacks against the full externally visible callback URL. If a proxy or tunnel changes the URL Django sees, configure Django/proxy forwarded-host handling so the reconstructed request URL matches the URL configured in Twilio. Callback signature checks fail closed when the auth token or signature is missing.
